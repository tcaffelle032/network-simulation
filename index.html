Grades 9–12 · 20–30 minutes

A network made of strings

Use the devices as virtual classmates. A string lets two devices communicate directly. A device can relay a message along several strings, creating an indirect path.

Suggested lesson flow

  1. Notice the problem · 2–3 minutes. Connect A–B, C–D, and E–F. Try to send from A to F. Ask why paired connections leave separate groups.
  2. Challenge 1 · 4 minutes. Everyone must speak directly to everyone else. Build the network. Ask how the number of strings grows as devices join.
  3. Challenge 2 · 4–5 minutes. Keep everyone connected using the fewest strings. Compare a chain with a star. Both can meet the cost goal, but messages travel different paths.
  4. Challenge 3 · 4–5 minutes. Keep everyone connected after any one string is cut. Test different strings, repair them, and improve the network. Ask why an alternate path helps.
  5. Challenge 4 · 4–6 minutes. Balance the string budget, survival of a cut, and maximum path length. Keep a design when moving between challenges so students can improve it.
  6. Reflect · 2–4 minutes. Download the design reasoning. Ask which compromise students chose and why no design is best for every situation.

How to use the builder

  • Connect: select two devices. Selecting an existing pair removes its string, including a cut string.
  • Cut / repair: select a string to toggle its failure. A cut string still counts as paid for. Repairing restores the original connection.
  • Test one string cut: the program cuts a vulnerable string when one exists. Otherwise it chooses a working string. Repair between trials to test the original design. You can also cut any string yourself.
  • Send message: watch a message move along a shortest path. One hop advances it one connection at a time. A crossing of strings is never a junction.
  • Teacher tools: show example designs and highlight vulnerable strings. Turn this off for independent work. Examples are optional and replace the current strings. Undo restores the previous design.
  • Projector view: enlarges the working area and hides the reflection and file controls. Click again to return. Use your browser’s full-screen control if desired.
  • Save design: download the current network and all four reflections. Open design restores that file on any computer with this simulator.

Teacher reference

For n devices, a direct connection for every pair needs n(n − 1)/2 strings. A connected network needs at least n − 1 strings. A connected network that survives any single string cut needs at least n strings for n ≥ 3. A ring achieves that minimum.

A star keeps paths short while relying on its central device and each individual string. A ring offers an alternate path after a string cut, but messages may need more hops. More connections can reduce hops and improve resilience while increasing cost.

The automatic single-cut check tries every working string individually. “Risky” means removing that string disconnects the current working network. If the network is already separated, connect it before judging whole-network resilience.

Vocabulary

Computing device
A machine that can run a program, such as a computer, router, tablet, or server.
Computing system
Computing devices and programs working together for a common purpose.
Computing network
Interconnected computing devices capable of sending or receiving data.
Path
The sequence of connections from a sender to a receiver.
Bandwidth
The maximum amount of data that can be sent in a fixed amount of time, usually in bits per second. This simulator compares hops and does not measure bandwidth.

Model boundaries

Every string has equal cost, whatever its drawn length. Links work in both directions. Devices can relay messages, and a central route calculation chooses a shortest path. This models connectivity and alternate routes. Real networks use protocols and routers and have unequal delays, capacities, and costs. A string cut models a link failure, not a device failure.
